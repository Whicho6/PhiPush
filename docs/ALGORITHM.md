# PhiPush 推分算法

本文记录当前实现使用的数学规则和推荐 heuristic。它用于解释代码行为，不代表 Phigros 官方规范，也不保证推荐结果符合每位玩家的实际体感。

## 单谱 RKS

设谱面定数为 `C`，ACC 百分数为 `A`：

```text
A < 70:  rks = 0
A ≥ 70:  rks = C × ((A - 55) / 45)²
```

反推目标 ACC 时使用：

```text
A = 55 + 45 × sqrt(target_rks / C)
```

正 RKS 在 70% 处存在边界，因此反推结果不会返回低于 70% 的有效目标；超过谱面定数的目标 RKS 不可达。

## P1–P3 与 B1–B27

总 RKS 使用固定 30 个槽位：

- `P1–P3`：已达到 100% 的谱面中单谱 RKS 最高的 3 张
- `B1–B27`：全部有效成绩中单谱 RKS 最高的 27 张
- 总 RKS：上述槽位单谱 RKS 之和除以 30

同一张 100% 谱面可以同时进入 P 槽与 B 槽，因此可能贡献两次。不足 3 张 100% 谱面时，空缺 P 槽按 0 处理，不由额外 B 槽补位。

当前 cutoff 指 B27 的单谱 RKS。某张谱面的新成绩超过入选线后，算法会重建整个集合，确认它是否进入 B27、替换哪张谱面，以及总 RKS 的实际变化。

## ACC 候选

对每张定数已知且未达到 100% 的谱面，当前实现会组合以下候选：

- 当前 ACC 增加 `0.1 / 0.25 / 0.5 / 1 / 1.5 / 2` 个百分点
- `98 / 98.5 / 99 / 99.5 / 99.7 / 99.85 / 100%` 等精度节点
- 刚好越过当前 B27 cutoff 所需的 ACC
- 让游戏内两位小数显示跨到下一档所需的近似最低 ACC

每个候选都会重新计算 P1–P3 与 B1–B27，而不是简单按定数或当前 ACC 排序。100% 候选会把 P 槽增益和 B 槽增益分开计算。

## effort 与 recommendation score

当前推荐分数可概括为：

```text
effort = ACC 提升量 × 凸形高精度惩罚 + 100% 额外惩罚
score = predicted total RKS gain / effort
```

高精度惩罚在 97%、99% 和 99.8% 后逐渐加陡，避免把 `99.90 → 100.00` 与普通的 0.1 个百分点提升视为相同成本。跨越下一档两位小数显示线的候选获得很小的可解释加权。

`effort` 是保守的练习成本代理，不是谱面难度预测模型。它没有使用玩家历史练习时间、谱面配置、手法短板或个人稳定性。

## 目标 RKS 路线

目标路线使用贪心算法：

1. 在当前成绩集合上计算可用机会。
2. 选择 recommendation score 最高的候选。
3. 将该候选作为暂时已完成的成绩更新到工作副本。
4. 重新计算全部 P/B 槽位和下一步机会。
5. 达到目标、没有合理机会或达到 10 步时停止。

路线是逐步重算的近似方案，不是组合优化意义上的全局最短解。

## 当前局限

- 不知道玩家对具体谱面的真实体感难度
- 没有读取个人历史成绩曲线或练习时长
- 固定的高精度惩罚不能代表所有玩家
- 贪心路线可能错过先做低收益铺垫、后获得更优组合的方案
- 曲库定数或游戏规则变化会直接影响结果
- 输出是 estimate，不构成达到目标 RKS 的保证

实现位于 `app/services/rks.py` 与 `app/services/push_planner.py`，相应边界与排序由 pytest 覆盖。
